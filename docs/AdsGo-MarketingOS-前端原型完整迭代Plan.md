# AdsGo × Marketing OS 前端原型完整迭代 Plan

> 文档用途：前端原型迭代方案审阅与实施依据  
> 关联文档：[AdsGo-MarketingOS-产品融合立项方案.md](./AdsGo-MarketingOS-产品融合立项方案.md)  
> 版本：V1.0  
> 日期：2026-07-16  
> 实施范围：仅前端功能、交互和 Mock 状态闭环，不要求真实后端、模型或广告平台接入

---

## 1. 本轮迭代要解决什么

当前原型已经具备 Skill、知识库、Luna、广告管理、效果复盘、管理后台和分发等页面，但多数能力以独立卡片或预置结果存在。了解产品背景的人可以通过讲解理解产品，第一次接触项目的用户却需要自己跨页面拼接逻辑。

本轮迭代不以增加更多业务页面为目标，而是让任何第一次使用原型的人，都能通过页面信息和实际操作理解以下六个问题：

1. 平台如何把优秀优化师的方法变成 Skill；
2. 新品牌如何快速获得适合自己的服务能力；
3. Luna 如何组合 Skill、知识、品牌目标和数据；
4. 优化师如何使用、修改或拒绝 Luna 的判断；
5. 系统如何根据执行结果越来越理解当前品牌；
6. 多个品牌的有效经验如何被抽象为新的行业能力。

### 1.1 本轮成功标准

用户不需要阅读立项文档，也不需要演示人员补充解释，即可：

- 区分平台能力管理与品牌日常运营；
- 看懂 Skill 是一种结构化工作方法，而不是一段说明文字；
- 完成一次行业能力发布与品牌装配；
- 查看 Luna 判断所使用的完整上下文；
- 对建议进行采纳、修改或拒绝；
- 将执行结果验证并沉淀为品牌知识；
- 将多品牌共性经验审核为行业能力新版本并再次分发。

## 2. 当前原型的主要问题

### 2.1 平台后台与品牌工作区边界不清

当前管理后台虽然受平台管理员权限保护，但仍处于品牌工作空间路由和页面框架中，入口也来自品牌 Skill 页面。这会让用户误以为行业 Skill 是某个品牌的配置。

需要明确形成两个产品空间：

```text
平台能力管理后台
负责生产、审核、发布和分发公共能力

品牌经营工作空间
负责装配、适配、使用和反馈品牌能力
```

### 2.2 Skill 创建只是在填写基础资料

当前行业 Skill 编辑仅包含名称、说明、行业、版本和状态，不能说明一个优秀优化师的方法如何被结构化。

一个可被理解的 Skill 至少需要呈现：

- 解决的问题；
- 触发条件；
- 输入数据；
- 引用知识；
- 判断步骤；
- 输出结构；
- 是否产生业务动作；
- 人工确认规则；
- 效果验证方式。

### 2.3 新品牌装配停留在预览

现有分发中心可以选择 Skill、知识和目标品牌，但“行业能力包”没有真正写入品牌状态，新品牌创建后也不会进入能力推荐和适配过程。

### 2.4 Luna 的组合逻辑不够透明

当前 Luna 判断页面已经展示部分依据，但用户还不能完整查看：

- 调用了哪个 Skill 及哪个版本；
- 使用了哪个数据视图；
- 引用了哪些行业知识和品牌知识；
- 读取了什么品牌目标；
- 行业规则与品牌规则发生冲突时如何处理；
- 最终结论与原始行业建议有什么不同。

### 2.5 学习链路依赖预置数据

动作、效果、候选知识和行业候选已经存在，但多数是初始化数据。用户刚刚执行并验证的动作，不一定自动产生相应候选知识；多品牌行业候选也无法查看其证据来源。

### 2.6 原型缺少可连续演示的产品故事

产品不应该强迫日常工作遵循单一路径，但原型需要提供一条可选的完整演示主线，帮助第一次接触产品的用户理解所有模块之间的关系。

## 3. 总体改造策略

本轮采用“两个工作空间、一条演示主线、六个可验证闭环”的设计。

### 3.1 两个工作空间

#### A. 平台能力管理后台

面向平台管理员，负责：

- 将专家方法生产为行业 Skill；
- 维护 L1–L3 公共知识；
- 审核多品牌候选经验；
- 管理 Skill 版本；
- 组装行业能力包；
- 按行业或指定品牌分发 Skill 与知识；
- 查看能力覆盖和使用效果。

#### B. 品牌经营工作空间

面向品牌所有者、管理员和优化师，负责：

- 配置品牌画像、产品、目标和数据；
- 接收和装配平台分发的行业能力；
- 配置品牌私有 Skill 与 L4 知识；
- 使用 Luna 和业务页面处理日常工作；
- 执行、验证并沉淀品牌经验。

### 3.2 一条可选演示主线

增加“产品演示”入口或首次访问引导。它只负责帮助用户理解产品，不改变日常业务页面的非线性使用方式。

```text
专家方法
  → 行业 Skill
  → 发布与分发
  → 新品牌装配
  → Luna 组合上下文
  → 优化师决策
  → 执行与验证
  → 品牌知识
  → 多品牌抽象
  → 行业能力升级
```

用户可以随时退出演示，自由进入任意业务页面。

### 3.3 六个可验证闭环

每个问题必须有完整的“输入—操作—结果—下一步”，不能只展示说明卡片。

## 4. 目标信息架构

### 4.1 平台能力管理后台

建议使用独立后台框架与独立路由，例如：

```text
/admin
├── overview                 能力运营总览
├── skills                   行业 Skill
│   ├── library              Skill 列表
│   ├── editor/:id           Skill 结构化编辑器
│   └── versions/:id         版本与发布记录
├── knowledge               公共知识库
├── candidates              行业候选能力
├── packages                行业能力包
└── distribution            分发中心
```

后台顶部固定显示“平台能力管理后台”，不显示当前品牌，不使用品牌工作区侧边栏。右上角提供“返回品牌工作区”。

### 4.2 品牌经营工作空间

保留现有日常运营结构：

```text
今日工作台
计划与策略
广告运营
创意库
分析与复盘
品牌基础配置
能力与协作配置
```

其中“Skill 与知识库”只负责当前品牌能力：

- 查看平台已分发或品牌已选择的行业 Skill；
- 查看当前品牌 L1–L4 知识；
- 启停行业能力；
- 配置品牌适配参数；
- 创建品牌私有 Skill；
- 审核品牌候选知识；
- 查看最终生效能力。

品牌工作区不得出现平台分发操作。

### 4.3 原型角色切换

为了让评审人员能完整体验两个空间，前端原型提供明确的“演示身份”切换：

- 平台管理员；
- 品牌所有者；
- 品牌管理员；
- 普通成员 / 优化师。

身份切换只用于 Mock 演示，同时应即时改变菜单、权限提示和可操作按钮。

### 4.4 品牌管理员与优化师如何用得明白

平台管理员理解能力如何生产和分发，只解决了平台侧问题。品牌工作区还必须让品牌管理员和优化师在进入系统后快速明白三个问题：

1. 今天与我有关的事情是什么；
2. 哪些事情需要我决定，哪些事情只是查看；
3. 完成当前操作后，结果会进入哪里。

因此，品牌工作区不能让两个角色面对完全相同的页面重点。

#### 品牌管理员的产品任务

品牌管理员主要负责“确保品牌服务能力正确运转”，其首页重点应为：

- 待确认的平台能力升级；
- 新分发但尚未完成适配的 Skill 与知识；
- 品牌 Skill 或自动化的配置异常；
- 待审核的品牌候选知识；
- 需要管理员确认的高影响动作；
- 数据条件缺失；
- 成员与权限待处理事项；
- 报告、任务和预警的运行健康度。

品牌管理员不应该进入系统后先面对大量 Campaign 指标，也不应该从通知中心猜测哪些事项属于品牌治理。

建议在今日工作台增加“品牌管理待办”区域，并使用明确的任务语言：

```text
待完成能力适配：2 项
待审核品牌经验：3 条
待处理能力升级冲突：1 项
自动化运行异常：1 项
```

每个事项都应提供直接操作按钮，而不是只跳转到一个列表首页。

#### 优化师的产品任务

优化师主要负责“发现问题、形成判断、执行动作并验证结果”，其首页重点应为：

- 今日关键异常；
- Luna 待确认建议；
- 待执行运营动作；
- 观察期即将结束的动作；
- 本周策略待办；
- 待生成或交付的报告；
- 最近被品牌规则修正过的 Luna 判断。

优化师默认不需要理解 Skill 的完整配置方式，也不需要进入平台分发和成员管理。页面首先应该使用业务语言：

```text
美国冷启动 ROAS 连续 3 日低于目标
Luna 建议降低预算并替换疲劳素材
品牌促销规则已保护再营销 Campaign
需要你确认冷启动预算调整
```

只有点击“为什么这样判断”后，才展开 Skill、知识、数据和规则合成详情。

#### 同一个今日工作台的角色化呈现

不为每个角色再创建一套重复首页，而是在同一个今日工作台中根据角色调整排序和操作：

| 内容 | 品牌管理员 | 优化师 |
| --- | --- | --- |
| 品牌能力健康 | 首屏显示 | 收起或仅异常时显示 |
| 候选知识审核 | 直接审核 | 只查看自己贡献的反馈 |
| Luna 建议 | 查看高影响建议和审批 | 处理全部授权建议 |
| 运营动作 | 查看风险和阻塞 | 执行与验证 |
| 成员管理 | 可进入 | 不显示 |
| Skill 配置 | 可编辑和适配 | 只查看当前判断所用能力 |
| 平台分发 | 不显示 | 不显示 |

#### 页面必须回答的四个问题

每个主要业务页面的顶部上下文条统一回答：

- **你在哪里：** 当前品牌、模块和对象范围；
- **这里解决什么：** 用一句业务语言解释页面责任；
- **你现在要做什么：** 当前角色最重要的 1–3 个事项；
- **做完会去哪里：** 说明结果写入的模块和下一状态。

例如广告管理页面不写成“Campaign、AdSet、Ad 预算处理”，而应结合当前事项显示：

> 在这里确认并执行已经形成的广告动作。执行结果会进入“效果与复盘”，Luna 不会未经确认直接修改预算。

#### 权限反馈不能依赖用户猜测

权限设计采用三种明确状态：

1. **可操作：** 正常显示按钮；
2. **可查看但不可操作：** 显示只读原因，例如“仅品牌所有者或管理员可修改”；
3. **与角色无关：** 不显示入口，避免普通成员看到平台后台或成员管理。

不能让按钮点击后才提示无权限，也不能用统一禁用态替代权限解释。

#### 新用户首次进入

品牌管理员和优化师分别提供不超过 4 步的轻量引导：

品牌管理员：

```text
确认品牌目标
→ 检查已装配能力
→ 处理适配冲突
→ 开始品牌运营
```

优化师：

```text
查看今日重点
→ 打开 Luna 判断依据
→ 处理一条建议
→ 查看动作验证位置
```

引导完成后不再强制出现，并可从帮助入口重新启动。

#### 空状态也要说明下一步

新品牌或暂无事项时，不能只显示“暂无数据”：

- 没有 Skill → 说明需要管理员完成能力装配；
- 没有数据 → 引导检查数据集和广告账号；
- 没有建议 → 允许主动运行一次适用 Skill；
- 没有待办 → 展示最近完成事项和下一次自动任务；
- 没有候选知识 → 说明候选知识如何从决策和效果验证产生。

#### 角色可理解性验收

未阅读文档的品牌管理员进入后，应在 30 秒内指出：

- 当前品牌有哪些能力异常或待确认事项；
- 在哪里审核候选知识；
- 在哪里处理 Skill 升级冲突；
- 哪些动作需要管理员确认。

未阅读文档的优化师进入后，应在 30 秒内指出：

- 今天最需要处理的问题；
- Luna 建议做什么；
- 如何查看判断依据；
- 如何修改或拒绝；
- 执行后在哪里验证效果。

## 5. 六个问题的具体改造方案

## 5.1 平台如何把优秀优化师的方法变成 Skill

### 改造页面

平台后台新增“Skill 结构化编辑器”，替代当前简单表单。

### 编辑器结构

#### 第一步：定义工作问题

- Skill 名称；
- 适用行业；
- 解决的问题；
- 典型使用场景；
- 不适用场景。

#### 第二步：定义触发与输入

- 主动调用、定时任务、预警触发；
- 所需数据集；
- 所需数据视图或字段；
- 所需品牌上下文；
- 数据完整性条件。

#### 第三步：组织判断依据

- 选择 L1–L3 公共知识；
- 配置行业指标基准；
- 标记允许被品牌覆盖的规则；
- 设置禁止被品牌覆盖的安全规则。

#### 第四步：编排方法步骤

以可排序步骤呈现优化师方法，例如：

```text
1. 读取近 7 日与前 7 日指标
2. 对比行业基准和品牌目标
3. 判断是否处于学习期或促销保护期
4. 区分冷启动与再营销场景
5. 生成预算调整、保留或观察建议
```

支持新增、编辑、删除和拖动排序。

#### 第五步：定义输出与权限

- 输出类型：分析、建议、预警、任务、报告；
- 输出字段；
- 可写入的产品模块；
- 是否生成运营动作；
- 哪些动作必须人工确认；
- 哪些角色可以确认。

#### 第六步：定义效果验证

- 观察窗口；
- 验证指标；
- 有效、无效和继续观察的条件；
- 是否允许形成品牌候选知识；
- 是否允许进入跨品牌聚合。

### 模拟交互

1. 选择预置的“资深优化师方法笔记”；
2. 点击“提取为 Skill 草稿”；
3. 页面自动填充结构化字段；
4. 用户修改步骤和规则；
5. 点击“试运行”；
6. 显示一组示例数据、判断过程和输出；
7. 点击“发布 v1.0”；
8. Skill 进入可分发状态。

### 验收结果

用户能够回答：Skill 不是 Prompt，而是包含问题、数据、知识、步骤、输出、权限和验证的一套标准工作方法。

## 5.2 新品牌如何快速获得适合自己的服务能力

### 改造入口

新建品牌完成后，进入“品牌能力装配向导”，而不是直接进入空工作区。

### 装配向导

#### 第一步：确认品牌基础

- 行业；
- 经营模式；
- 主要市场；
- 核心产品；
- 当前经营阶段。

#### 第二步：配置经营边界

- ROAS / CPA 目标；
- 预算上限；
- 促销期；
- 客户红线；
- 高影响动作确认规则。

#### 第三步：系统推荐能力包

展示推荐原因，而不是只展示数量：

- 推荐的行业 Skill；
- 推荐的 L1–L3 知识；
- 推荐的数据视图模板；
- 推荐的任务和预警模板；
- 推荐的报告模板；
- 当前缺失的数据条件。

#### 第四步：品牌适配

逐项显示：

```text
行业默认规则
品牌目标或私有规则
冲突处理结果
最终生效规则
```

#### 第五步：完成装配

点击“启用品牌服务能力”后，Mock 状态一次性写入：

- 品牌 Skill；
- 已分配公共知识；
- 默认数据视图；
- 定时任务；
- 预警规则；
- 报告模板；
- 装配记录。

### 与平台分发的关系

- 平台分发决定品牌“可以获得什么”；
- 品牌装配决定品牌“启用什么、如何适配”；
- 普通成员不能执行装配；
- 所有者和品牌管理员可以确认装配结果。

### 验收结果

用户能够新建一个品牌，并在一次连续流程中让该品牌从空空间变成具备可用服务能力的工作空间。

## 5.3 Luna 如何组合 Skill、知识、品牌目标和数据

### 改造页面

重构“今日工作台”中的 Luna 服务事项卡，将其拆为三个可展开层次。

### 第一层：业务问题

默认只显示优化师真正关心的信息：

- 发生了什么；
- 影响哪个市场、Campaign、素材或产品；
- 严重程度；
- Luna 建议做什么。

### 第二层：判断依据

点击“查看判断依据”后打开右侧抽屉，分四组展示：

| 上下文 | 展示内容 |
| --- | --- |
| Skill | 名称、来源、版本、触发方式、关键步骤 |
| 知识 | 行业基准、市场动态、品牌私有经验及来源 |
| 品牌目标 | KPI、预算边界、经营阶段和特殊红线 |
| 数据 | 数据视图、时间范围、指标值和数据完整性 |

### 第三层：规则合成过程

明确展示 Luna 如何得出最终结果：

```text
行业 Skill 原始判断
      ↓
品牌目标约束
      ↓
L4 品牌规则覆盖
      ↓
数据条件检查
      ↓
最终建议与人工确认要求
```

冲突项使用明显但克制的提示，例如：

- 行业建议：降低全部低 ROAS Campaign 预算；
- 品牌规则：促销期保护高意向再营销预算；
- 最终结果：仅降低冷启动预算，再营销进入 48 小时观察。

### 模拟交互

- 切换数据视图后重新生成判断；
- 关闭某项品牌知识后显示建议变化；
- 切换经营阶段后显示行业规则与品牌规则重新合成；
- 所有变化只更新 Mock 结果，不要求真实 AI。

### 验收结果

用户不仅看见 Luna 的答案，还能解释为什么同一个行业 Skill 在不同品牌上会得出不同建议。

## 5.4 优化师如何使用、修改或拒绝 Luna 的判断

### 决策交互

每条可执行建议统一提供：

- 采纳；
- 修改后采纳；
- 拒绝并说明；
- 暂时观察。

### 采纳

点击后先展示即将写入的位置和影响：

- 预算动作进入广告管理；
- 素材建议进入素材库或草稿中心；
- 周期工作进入自动化配置；
- 团队事项进入策略待办；
- 所有高影响动作仍等待人工执行。

### 修改后采纳

不能再使用只读字段。用户需要真正编辑：

- 预算数值或调整比例；
- 适用对象；
- 执行时间；
- 观察窗口；
- 修改原因。

确认后同时保存：

- Luna 原始建议；
- 优化师最终动作；
- 修改差异；
- 修改原因；
- 关联 Skill、知识、目标和数据视图。

### 拒绝并说明

拒绝原因采用“结构化选项 + 补充说明”：

- 数据判断不准确；
- 品牌特殊要求；
- 当前处于学习期；
- 客户明确要求；
- 风险过高；
- 其他。

提交后生成品牌学习候选，但不直接改变正式知识或 Skill。

### 暂时观察

允许用户设置：

- 观察时长；
- 关注指标；
- 重新提醒条件。

到期后进入今日工作队列。

### 决策后反馈

操作完成后必须显示：

```text
你的决策已记录
→ 去广告管理执行
→ 去动作与复盘查看
→ 查看本次判断证据
```

### 验收结果

用户能够真实修改建议值，并清楚知道采纳、拒绝或观察之后信息去了哪里。

## 5.5 系统如何根据结果越来越理解当前品牌

### 改造核心

将“动作验证”和“品牌候选知识”改为真实状态联动，不再只依赖预置卡片。

### 状态流程

```text
Luna 建议
  → 优化师决策
  → 运营动作
  → 标记执行
  → 观察窗口
  → 验证结果
  → 自动生成品牌候选知识
  → 品牌管理员审核
  → L4 知识或品牌 Skill 规则
  → 下一次 Luna 判断引用
```

### 效果验证表单

用户选择“有效、无效、继续观察”，并填写或选择：

- 执行后指标；
- 与执行前的变化；
- 可能原因；
- 适用条件；
- 是否建议复用。

### 自动生成品牌候选知识

验证完成后，根据动作类型生成不同候选：

- 有效动作 → 有效品牌经验；
- 无效动作 → 风险或不适用条件；
- 多次修改 → 品牌偏好或品牌规则；
- 多次拒绝 → 客户红线候选；
- 报告反馈 → 报告偏好候选。

### 品牌审核

品牌所有者或管理员可以：

- 采纳为 L4 品牌知识；
- 采纳为品牌 Skill 覆盖规则；
- 继续观察；
- 忽略。

采纳后，下一次相同 Luna 场景必须在判断依据中显示这条新知识，并改变最终建议。

### 验收结果

用户可以亲手完成一次“验证有效—采纳知识—重新分析—建议变化”的循环。

## 5.6 多品牌有效经验如何被抽象为行业能力

### 改造页面

平台后台“行业候选能力”不再只展示预置摘要，而是提供可查看的证据聚合详情。

### 候选形成

当多个品牌存在同类、已审核且允许聚合的经验时，Mock 系统生成行业候选：

- 使用品牌数量；
- 相关动作数量；
- 有效与无效数量；
- 共同适用条件；
- 共同不适用条件；
- 优化师修改和拒绝模式；
- 脱敏处理状态。

页面只显示匿名品牌编号和聚合指标，不显示品牌名称、具体预算、客户信息或 L4 私有内容。

### 平台审核流程

平台管理员可以选择：

- 新增行业知识；
- 更新现有行业知识；
- 新建行业 Skill；
- 生成现有 Skill 新版本；
- 暂不采用。

若选择“生成 Skill 新版本”，进入结构化差异编辑：

```text
当前版本规则
候选新增条件
影响的输出与验证方式
兼容性风险
建议版本号
```

发布后真正创建行业 Skill 新版本，而不是只向某个品牌生成升级提醒。

### 再分发

新版本发布后进入分发中心：

- 按客户行业分发；
- 单选或多选品牌分发；
- 仅提醒品牌升级；
- 自动升级无冲突品牌；
- 对存在品牌覆盖冲突的品牌要求人工确认。

### 验收结果

用户可以从多个匿名品牌证据出发，生成行业 Skill 新版本，并将其再次分发给目标品牌。

## 9. 关键状态联动

本轮必须优先保证以下前端联动真实发生：

1. 发布行业 Skill → 出现在分发中心；
2. 平台确认分发 → 出现在目标品牌待装配能力；
3. 品牌完成装配 → 生成品牌 Skill、知识、任务和模板；
4. Luna 发起分析 → 读取当前品牌实际装配状态；
5. 修改后采纳 → 同时保存原建议和最终动作；
6. 标记执行 → 动作进入验证中；
7. 验证完成 → 自动生成品牌候选知识；
8. 候选知识采纳 → 写入 L4 知识或品牌 Skill 覆盖规则；
9. 重新分析 → Luna 判断依据与结论发生变化；
10. 多品牌有效结果达到条件 → 生成行业候选；
11. 行业候选发布 → 创建行业 Skill 新版本；
12. 新版本分发 → 目标品牌出现升级或冲突确认。

任何一步都不能只弹出“操作成功”而没有改变后续页面状态。

## 10. UI 与 UX 原则

### 10.1 产品空间优先于视觉装饰

- 平台后台与品牌工作区使用不同导航框架和空间标识；
- 不依赖颜色区分权限，必须有明确文字；
- 平台后台不显示品牌级菜单；
- 品牌工作区不出现平台分发按钮。

### 10.2 先显示业务结论，再按需展开系统逻辑

优化师默认看到问题、影响和建议。Skill、知识、规则合成等解释放入可展开抽屉，避免把日常页面设计成技术后台。

### 10.3 每个操作都交代去向

操作完成提示不能只有“成功”，必须说明：

- 创建了什么对象；
- 写入了哪个模块；
- 当前处于什么状态；
- 下一步可以做什么。

### 10.4 不把产品理解成僵硬流水线

- 问题可以来自 Luna、数据洞察、预警、策略、广告管理、素材或人工发现；
- 草稿中心只暂存待发布 Campaign；
- 创编与发布是工具，不是所有决策的必经页面；
- 动作根据类型进入对应执行模块；
- 演示主线是说明工具，不是对日常工作路径的限制。

### 10.5 原型以功能表达为先

- 复用现有组件与视觉规范；
- 不投入复杂动效和生产级边界处理；
- 重点实现可点击、可修改、可回看和跨页面状态变化；
- 避免继续增加没有交互结果的统计卡片。

## 12. 验收用例

### 用例一：方法沉淀

用户能从一份优化师方法笔记创建、试运行并发布行业 Skill，且能复述 Skill 的输入、步骤、输出和验证方式。

### 用例二：品牌迁移

用户能创建新品牌，看到行业推荐，完成能力装配，并在品牌 Skill 页面看到最终生效能力。

### 用例三：Luna 判断

用户能指出当前建议使用的 Skill 版本、知识、目标和数据视图，并看懂品牌规则如何改变行业默认结果。

### 用例四：人工控制

用户能修改 Luna 建议的数值和对象，或填写拒绝原因，并能找到后续生成的动作或学习候选。

### 用例五：品牌学习

用户能验证一个动作、生成候选知识、审核进入 L4，并看到重新分析后的 Luna 建议发生变化。

### 用例六：平台进化

用户能查看匿名多品牌证据，将候选经验发布为行业 Skill 新版本，并再次完成分发。

### 用例七：品牌管理员日常使用

切换为品牌管理员后，用户无需进入多个菜单查找，即可在今日工作台完成：

1. 查看品牌能力健康状态；
2. 处理一项待适配的行业 Skill；
3. 审核一条品牌候选知识；
4. 处理一项 Skill 版本冲突；
5. 确认一个高影响运营动作；
6. 返回工作台查看待办数量和状态变化。

过程中不得出现平台分发操作，也不得要求用户进入平台能力管理后台。

### 用例八：优化师日常使用

切换为普通成员 / 优化师后，用户无需理解 Skill 配置细节，即可完成：

1. 找到今日最高优先级异常；
2. 查看 Luna 的业务建议；
3. 按需展开 Skill、知识、目标和数据依据；
4. 修改建议并填写原因；
5. 将动作推进到执行和验证；
6. 查看自己的反馈如何成为品牌学习候选。

过程中不得显示成员管理、品牌 Skill 编辑和平台后台入口。

### 最终无讲解测试

邀请未阅读产品文档的测试用户分别以平台管理员、品牌管理员和优化师身份独立使用原型。体验结束后要求其回答最初六个问题，并完成对应角色用例。六个问题均能结合页面操作正确解释，且角色任务没有误入其他权限空间，才视为本轮完成。

## 13. 本轮不做什么

- 不接入真实广告平台；
- 不实现真实数据同步；
- 不调用真实 LLM；
- 不实现真实任务调度；
- 不实现真实跨品牌数据聚合；
- 不实现生产级权限后端；
- 不实现复杂版本回滚；
- 不追求生产级视觉精修；
- 不新增与六个核心问题无关的外围功能。

所有结果通过前端 Store、Mock 数据和可重置的演示状态完成。

---

## 14. 最终交付结果

完成本轮后，原型应当同时具备三种表达能力：

### 对平台管理员

能够展示专家方法如何成为行业 Skill，如何结合公共知识形成能力包，并向目标品牌分发和升级。

### 对品牌和优化师

能够展示品牌如何快速装配能力，Luna 如何基于品牌上下文工作，以及人如何控制 AI 的判断与执行。

### 对立项评审者

能够通过一条完整可操作案例理解产品的双重增长逻辑：

```text
单品牌使用越久，Luna 越理解该品牌
                +
平台服务品牌越多，行业能力越成熟
```

本轮迭代的最终目标不是让原型“页面更多”，而是让用户亲手验证：

> 优秀营销方法可以被结构化、分发到品牌、在品牌上下文中被 Luna 使用，并根据真实服务反馈持续进化。
