> 文档用途：产品立项与产品共识  
> 文档版本：V2.0  
> 更新日期：2026-07-16

## 1. 产品定义

### 1.1 一句话定义

AdsGo Marketing OS 是一套服务于广告优化师和品牌经营团队的 AI 营销操作系统：它将优秀优化师的工作方法沉淀为可管理、可分发的 Skill，将行业知识与品牌经验组织成持续更新的知识体系，再由 Luna 把这些能力应用到不同品牌的计划、分析、执行和复盘中。

它的目标不是替代一个广告媒体后台，也不是增加一个通用 AI 聊天窗口，而是建立一套能够复制营销服务能力、保留品牌差异、并通过实际结果持续学习的工作系统。

### 1.2 产品解决的核心问题

广告优化服务长期面临三个结构性问题。

第一，优秀经验掌握在人脑中，难以复制。

- 资深优化师知道什么时候该降预算、什么时候应该保留学习期；
- 知道不同阶段应该看哪些指标、如何判断素材疲劳；
- 知道客户有哪些不能触碰的红线；
- 但这些经验通常存在于个人习惯、聊天记录和零散文档中。

第二，同一套经验不能直接套用到所有品牌。

- 行业方法具有共性；
- 不同品牌的产品、目标、预算承受能力和客户偏好不同；
- 如果只复制通用规则，AI 会给出“看似正确但不适合当前品牌”的建议。

第三，服务过程没有形成学习闭环。

- 建议被采纳后，系统不知道结果是否有效；
- 优化师拒绝建议时，原因没有被结构化保存；
- 新优化师接手品牌时，需要重新理解全部背景；
- 同一类问题会被反复分析，服务效率无法随使用时间提高。

本产品要解决的，就是如何将“人的专业服务能力”变成“平台可管理的能力”，同时保留每个品牌的差异，并让每次服务结果继续提升下一次判断。

### 1.3 产品核心价值

产品的核心价值可以概括为三个词：沉淀、迁移、进化。

| 核心价值 | 含义 |
| --- | --- |
| 沉淀 | 将优化师的方法、行业知识、品牌偏好和有效经验变成结构化资产 |
| 迁移 | 将已经验证的服务能力快速应用到新品牌，同时保留品牌差异 |
| 进化 | 根据采纳、拒绝、执行结果和复盘反馈持续修正后续判断 |

## 2. 为什么 AdsGo 要与 Marketing OS 融合

### 2.1 AdsGo 原有能力的优势

AdsGo 已经覆盖广告运营中靠近执行的一侧：

- 媒体计划；
- Campaign、AdSet、Ad 管理；
- 预算调整；
- 素材库与素材生成；
- 广告草稿与批量发布；
- 投放数据与报告。

这些能力解决了“在哪里工作”和“如何执行”的问题，但仅靠执行工具还无法完整承载营销服务。

系统还需要知道：

- 为什么要这样做；
- 应该使用哪一种分析方法；
- 当前品牌有哪些特殊约束；
- 过去做过什么、结果怎么样；
- 哪些经验可以被下一个品牌复用。

### 2.2 Marketing OS 补足的能力

Marketing OS 带来的不是一组孤立页面，而是一套认知与学习机制：

- 品牌工作空间；
- 品牌画像与产品上下文；
- 数据集与可复用数据视图；
- 行业 Skill 与品牌 Skill；
- 分层知识库；
- 周期性策略；
- 定时任务与预警；
- 报告快照；
- 动作记录与效果验证；
- 经验审核与知识回流。

### 2.3 融合的必要性

如果不融合，两个系统分别只能完成一半工作：

```text
AdsGo
擅长计划、广告、素材和执行
但缺少可迁移的认知与学习体系

Marketing OS
擅长分析、知识、策略和复盘
但缺少深入广告执行场景的工作入口
```

融合后，产品才能形成完整链路：

```text
品牌上下文
    ↓
Skill 选择工作方法
    ↓
知识库提供判断依据
    ↓
数据视图提供经营事实
    ↓
Luna 生成策略与动作
    ↓
AdsGo 完成广告和素材执行
    ↓
效果验证产生新经验
    ↓
新经验回流 Skill 与知识体系
```

因此，本次融合不是把 Marketing OS 的页面搬入 AdsGo，而是给 AdsGo 增加一个能够管理、分发和进化营销服务能力的“大脑”。

## 3. 产品总体框架

### 3.1 四层产品架构

```text
┌──────────────────────────────────────────────────────────┐
│ 第一层：品牌经营工作空间                                 │
│ 计划 / 广告 / 素材 / 洞察 / 报告 / 复盘                 │
├──────────────────────────────────────────────────────────┤
│ 第二层：Luna 智能协作层                                  │
│ 理解问题 / 选择 Skill / 组织上下文 / 生成建议 / 推动动作 │
├──────────────────────────────────────────────────────────┤
│ 第三层：能力与认知层                                     │
│ 行业 Skill / 品牌 Skill / 行业知识 / 品牌知识            │
├──────────────────────────────────────────────────────────┤
│ 第四层：经营上下文层                                     │
│ 品牌 / 产品 / 目标 / 账号 / 数据集 / 数据视图 / 历史结果 │
└──────────────────────────────────────────────────────────┘
```

### 3.2 各层职责

#### 品牌经营工作空间

这是优化师日常工作的地方，负责承载具体业务动作：

- 制定媒体计划；
- 查看广告表现；
- 调整预算；
- 处理素材疲劳；
- 生成新素材；
- 查看数据洞察；
- 处理预警；
- 生成报告；
- 验证动作效果。

#### Luna 智能协作层

Luna 不是独立业务模块，而是连接全部业务模块的智能协作者。

它负责：

1. 理解优化师当前要解决的问题；
2. 找到适合当前问题的 Skill；
3. 组织品牌、产品、目标、数据和知识上下文；
4. 执行 Skill 并形成可解释的判断；
5. 将建议转换为可确认的业务动作；
6. 把结果写入计划、广告、素材、任务、报告或复盘；
7. 在优化师拒绝或修改建议时追问原因；
8. 将结果反馈到品牌认知体系。

#### 能力与认知层

这一层是产品实现规模化服务的关键。

- Skill 规定“如何完成一项工作”；
- 知识库提供“完成这项工作时应该知道什么”；
- 行业层负责通用能力；
- 品牌层负责个性化差异。

#### 经营上下文层

这一层描述当前服务对象的真实情况：

- 品牌是谁；
- 品牌销售什么产品；
- 当前经营目标是什么；
- 使用哪些广告账号；
- 有哪些数据；
- 过去采取过哪些动作；
- 哪些动作被验证有效。

没有这一层，Skill 只能提供通用答案；有了这一层，同一个 Skill 才能针对不同品牌产生不同结果。

## 4. 产品核心对象

| 对象 | 回答的问题 | 产品作用 |
| --- | --- | --- |
| 品牌 | 服务对象是谁 | 形成独立工作空间、权限和数据边界 |
| 产品 | 品牌在卖什么 | 连接卖点、受众、素材和策略 |
| 目标与阶段 | 当前要实现什么 | 为建议提供 KPI、预算和阶段约束 |
| 数据集 | 有哪些原始经营数据 | 提供广告、素材、订单和归因数据 |
| 数据视图 | 当前按什么口径观察业务 | 为分析、策略、任务和报告提供可复用取数方式 |
| Skill | 这项工作应该怎么做 | 封装工作方法、步骤、输入与输出 |
| 知识 | 做判断时应该知道什么 | 提供行业基准、最佳实践和品牌经验 |
| 策略 | 当前周期决定做什么 | 组织目标、判断和执行优先级 |
| 运营动作 | 实际做了什么 | 记录执行对象、依据、人员和时间 |
| 效果验证 | 做完是否有效 | 为复盘和经验沉淀提供事实依据 |

## 5. Skill：服务能力的最小管理单元

### 5.1 Skill 的产品定义

Skill 是一项可被 Luna 调用、可被平台管理、可被品牌启用的标准化营销工作能力。

它不是一段静态 Prompt，也不只是一个按钮。一个完整 Skill 至少描述：

- 解决什么问题；
- 在什么场景下触发；
- 需要读取哪些数据和知识；
- 按什么步骤分析；
- 输出什么结构；
- 是否产生业务动作；
- 哪些动作需要人工确认；
- 执行后用什么指标验证效果。

例如，“素材疲劳检查”Skill 不只是回答某个素材是否疲劳，而是形成完整工作逻辑：

```text
读取素材花费、CTR、CVR、频次和历史峰值
            ↓
引用行业疲劳基准
            ↓
引用品牌自己的频次红线和历史经验
            ↓
区分冷启动、再营销和稳定素材
            ↓
输出换新、保留或观察建议
            ↓
经优化师确认后形成素材动作
            ↓
在 48–72 小时后验证新素材效果
```

### 5.2 为什么必须对 Skill 分层

营销服务既有共性，也有品牌差异。

如果所有能力都做成品牌私有 Skill：

- 每接入一个新品牌都要重新配置；
- 优秀方法无法规模化复制；
- 平台无法建立统一服务标准。

如果所有能力都做成行业 Skill：

- 品牌特殊红线无法表达；
- 客户偏好会被通用规则覆盖；
- AI 建议容易失去品牌适配性。

因此产品采用两级 Skill 体系。

### 5.3 行业 Skill

行业 Skill 是由平台维护、面向某一行业或多行业品牌分发的公共服务能力。

典型行业 Skill 包括：

- 电商预算健康检查；
- 应用扩量机会识别；
- 素材疲劳预警；
- 再营销窗口诊断；
- 大促期间预算节奏检查；
- 周度经营报告生成。

行业 Skill 的价值是把优秀优化师的方法变成平台标准。

它适合承载：

- 通用分析步骤；
- 行业指标基准；
- 平台最佳实践；
- 风险判断框架；
- 标准输出结构；
- 通用效果验证方式。

### 5.4 品牌 Skill

品牌 Skill 是只服务当前品牌的个性化能力。

它适合承载：

- 品牌特有 KPI 红线；
- 客户约定的审批规则；
- 特殊预算保护策略；
- 品牌素材表达要求；
- 特定产品的投放逻辑；
- 与行业通用方法不同的例外规则。

例如，行业 Skill 可能认为低 ROAS 的再营销 Campaign 应该降预算，但品牌 Skill 可以规定：

> 促销周期间必须保留高意向再营销曝光，即使短期 ROAS 低于行业建议值，也只能进入观察，不可直接暂停。

品牌 Skill 不是完全重写行业能力，而是对公共能力进行品牌化补充、覆盖或约束。

### 5.5 Skill 库与能力分发

平台通过 Skill 库管理所有可用能力。

Skill 库中的每项能力需要明确标记：

- 行业 Skill；
- 品牌个性化 Skill；
- 适用行业；
- 解决的问题；
- 所需数据；
- 当前版本；
- 使用范围；
- 是否需要人工确认。

品牌所有者或管理员可以：

1. 从 Skill 库选择适用能力；
2. 将行业 Skill 添加到当前品牌；
3. 启用或停用某项能力；
4. 为当前品牌补充个性化参数；
5. 新增品牌私有 Skill；
6. 查看 Skill 在任务、预警和 Luna 中的使用情况。

普通成员使用 Skill 产生的业务结果，但不能修改 Skill 本身。

平台管理员负责行业 Skill 的创建、维护和发布，从而形成“平台生产能力、品牌选择能力、Luna 调用能力”的分发关系。

### 5.6 Skill 的继承关系

同一个工作场景中，Luna 按以下顺序组合能力：

```text
行业 Skill 的通用方法
        +
行业知识与基准
        +
品牌 Skill 的特殊规则
        +
品牌知识与历史经验
        +
当前数据与经营目标
        =
当前品牌的具体建议
```

品牌能力不是与行业能力并列执行，而是在行业能力之上形成适配层。

### 5.7 Skill 的反馈与优化

Skill 的价值不能只通过调用次数判断，还要观察其实际服务效果：

- 建议是否被采纳；
- 被拒绝的主要原因是什么；
- 优化师是否经常手动修改结果；
- 执行动作后核心指标是否改善；
- 哪些行业或品牌适配效果最好；
- 哪些条件下应该停止调用该 Skill。

这些反馈不会直接自动修改正式 Skill，而是形成 Skill 优化依据，由平台管理员或品牌管理员审核后更新。

## 6. 知识库：服务判断的长期记忆

### 6.1 知识库与 Skill 的区别

Skill 和知识库容易被混淆，但两者承担不同职责。

| 对象 | 核心含义 | 示例 |
| --- | --- | --- |
| Skill | 如何完成一项工作 | 如何检查预算健康、如何判断素材疲劳 |
| 知识 | 完成工作时需要引用的事实与经验 | 电商行业 CPA 基准、品牌促销周预算约束 |

Skill 是工作方法，知识是判断依据。

同一个“预算健康检查”Skill，在不同知识背景下会得到不同结果。

### 6.2 四层知识结构

#### L1：行业基础知识

描述行业的基本经营环境：

- 行业分类；
- 商业模式；
- 常见用户画像；
- 市场周期；
- 典型产品结构；
- 常见转化路径。

L1 帮助 Luna 理解“这个品牌所处的行业是什么样”。

#### L2：投放知识

描述广告运营中的通用方法和基准：

- 平台特征；
- 指标参考范围；
- 不同阶段的投放策略；
- 渠道最佳实践；
- 素材与受众方法；
- 常见异常模式。

L2 帮助 Luna 理解“在这个行业里通常应该怎么投”。

#### L3：竞品与市场动态

描述持续变化的外部环境：

- 竞品素材方向；
- 新品上线；
- 市场趋势；
- 消费者兴趣变化；
- 竞品渠道动作；
- 行业热点与季节性变化。

L3 帮助 Luna 理解“外部环境最近发生了什么”。

#### L4：品牌私有知识

描述当前品牌独有的事实与经验：

- KPI 和预算红线；
- 客户偏好；
- 特殊审批要求；
- 产品卖点；
- 历史有效策略；
- 被拒绝建议的原因；
- 已验证的运营经验；
- 报告表达偏好。

L4 帮助 Luna 理解“这个品牌与行业中的其他品牌有什么不同”。

### 6.3 知识的来源

知识不是只靠人工一次性录入，而是来自整个服务过程。

```text
平台管理员维护
    → 行业基础、基准和最佳实践

市场与竞品任务
    → 外部动态和变化

品牌画像与产品分析
    → 品牌定位、受众和卖点

优化师操作
    → 人工判断和特殊处理原因

Luna 追问
    → 客户偏好和拒绝原因

动作效果验证
    → 被实际结果证明有效或无效的经验

报告反馈
    → 客户偏好的报告内容和表达方式
```

### 6.4 知识审核机制

不是所有对话和动作都应该自动成为正式知识。

产品将知识分成三个状态：

```text
原始事实或反馈
      ↓
候选知识
      ↓
管理员审核
   ↙       ↘
采纳       忽略
  ↓
正式知识
```

这样可以避免：

- 把一次偶然结果当成长期规律；
- 将优化师临时处理方式固化；
- 让错误数据污染品牌记忆；
- 未经确认就改变品牌运营规则。

### 6.5 知识更新原则

不同知识具有不同更新频率：

| 知识类型 | 变化速度 | 维护方式 |
| --- | --- | --- |
| 行业基础 | 慢 | 平台管理员周期维护 |
| 投放基准 | 中 | 行业管理员与优化师共同维护 |
| 市场竞品 | 快 | 定时任务采集，管理员审核 |
| 品牌 KPI 与红线 | 中 | 品牌管理员维护 |
| 历史经验 | 持续积累 | 动作验证后形成候选知识 |
| 客户偏好 | 持续积累 | 对话追问和人工确认 |

## 7. 跨品牌迁移：产品如何复制服务能力

### 7.1 跨品牌迁移的定义

跨品牌迁移不是把品牌 A 的数据或私有经验复制给品牌 B，而是把已经验证的“工作方法”和“行业共性”迁移到新品牌，再结合新品牌自己的上下文完成适配。

迁移的对象包括：

- 行业 Skill；
- 通用分析流程；
- 标准指标体系；
- 报告结构；
- 任务模板；
- 预警模板；
- 行业知识与基准；
- 脱敏、抽象后形成的共性经验。

明确不能直接迁移的对象包括：

- 品牌私有数据；
- 客户名单和成员；
- 品牌私有 Skill；
- L4 品牌知识；
- 未脱敏的历史动作；
- 具体预算和商业机密。

### 7.2 新品牌的能力装配流程

当平台接入一个新品牌时，不再从空白开始配置全部服务，而是完成一次能力装配。

```text
创建品牌工作空间
      ↓
分析品牌画像和产品
      ↓
选择行业与经营模式
      ↓
系统推荐适用的行业 Skill
      ↓
装配行业知识与标准任务模板
      ↓
配置品牌目标、红线和例外规则
      ↓
形成品牌 Skill 与 L4 初始知识
      ↓
开始运行计划、分析和自动化任务
```

这样，新品牌可以直接获得平台已经积累的行业服务能力，同时又不会失去自身差异。

### 7.3 能力迁移的三个层次

#### 第一层：标准模板迁移

迁移最基础的服务结构：

- 指标看板模板；
- 数据视图模板；
- 定时任务模板；
- 预警规则模板；
- 报告模板；
- 周度策略流程。

这解决“新品牌如何快速开始工作”。

#### 第二层：行业能力迁移

迁移经过验证的行业方法：

- 行业 Skill；
- 行业指标基准；
- 常见异常模式；
- 行业素材与受众方法；
- 行业策略节奏。

这解决“新品牌如何立即获得专业判断能力”。

#### 第三层：经验抽象迁移

平台从多个品牌的服务结果中识别共性，但不直接共享品牌私有内容。

例如多个运动服饰品牌都出现：

- 高频次主视频导致冷启动 CPA 上升；
- 真实试穿 UGC 替换后转化改善；
- 再营销素材并未同时疲劳。

平台可以将其抽象为行业候选经验：

> 当冷启动素材频次超过特定区间且 CTR、CVR 同时衰减时，优先替换冷启动主素材，不应同步停止仍有效的再营销素材。

该经验经过平台审核后，可以进入行业知识或行业 Skill 的新版本，再分发给其他同类品牌。

### 7.4 跨品牌迁移的边界

产品必须遵循“迁移能力，不迁移秘密”的原则。

```text
允许迁移
方法、模板、指标定义、行业基准、抽象规律

禁止直接迁移
品牌数据、客户偏好、私有规则、具体预算、未脱敏案例
```

品牌 L4 知识只在当前品牌空间中被调用。只有经过脱敏、聚合、抽象和平台审核的共性结论，才可能上升为行业知识。

## 8. 产品如何越用越聪明

### 8.1 “聪明”不是对话次数增加

产品越用越聪明，不是因为 Luna 保存了更多聊天记录，而是因为系统持续获得结构化反馈：

- 哪项建议被采纳；
- 哪项建议被拒绝；
- 拒绝的原因是什么；
- 优化师最终做了什么；
- 动作后的指标如何变化；
- 哪项经验被管理员确认；
- 哪些 Skill 在什么品牌上有效；
- 哪类报告更符合客户需要。

### 8.2 单品牌学习闭环

```text
Luna 调用 Skill 生成建议
          ↓
优化师采纳 / 拒绝 / 修改
          ↓
系统记录决策及原因
          ↓
动作执行并进入观察窗口
          ↓
验证实际效果
          ↓
形成品牌候选知识
          ↓
品牌管理员审核
          ↓
更新 L4 品牌知识或品牌 Skill
          ↓
下一次 Luna 判断更加贴合该品牌
```

例如，Luna 多次建议降低再营销预算，但优化师说明客户在促销周要求保持曝光。该原因被确认后会进入品牌知识。下一次相同场景中，系统不再重复给出直接降预算建议，而是建议“保持预算并进入 48 小时观察”。

### 8.3 行业学习闭环

```text
多个品牌产生动作与效果结果
          ↓
平台识别可重复出现的模式
          ↓
去除品牌私有信息并进行抽象
          ↓
形成行业候选知识或 Skill 优化建议
          ↓
平台管理员审核
          ↓
发布行业 Skill / 行业知识新版本
          ↓
其他同类品牌获得更成熟的服务能力
```

### 8.4 三类反馈信号

#### 显性反馈

- 采纳；
- 拒绝；
- 填写拒绝原因；
- 编辑建议；
- 报告评分；
- 管理员采纳或忽略候选知识。

#### 行为反馈

- 优化师最终是否执行；
- 执行前是否修改预算或素材；
- 是否频繁跳过某个 Skill；
- 是否将结论加入策略或报告；
- 哪些数据视图被反复使用。

#### 结果反馈

- ROAS、CPA、CTR、CVR 等指标变化；
- 素材换新后的表现；
- 预警处理后异常是否消失；
- 策略待办的完成情况；
- 报告是否被查看和认可。

三类信号共同决定系统应该记住什么、修改什么、继续观察什么。

### 8.5 学习的安全原则

产品不能因为一次结果就自动改变正式规则。

学习过程遵循：

1. 先记录事实；
2. 再形成候选结论；
3. 区分品牌经验和行业规律；
4. 由有权限的人审核；
5. 正式更新 Skill 或知识；
6. 保留来源和适用条件。

这使产品能够进化，但不会因为噪声数据或一次偶然操作失控。

## 9. 优化师工作动线

### 9.1 日常工作不从“功能菜单”开始

优化师的工作不是依次打开每个页面，而是围绕问题推进。产品需要同时支持两种入口：

- 主动工作：优化师进入计划、广告、素材或洞察页面处理工作；
- 被动触发：Luna、定时任务或预警把需要关注的问题推送给优化师。

### 9.2 每日工作动线

#### 第一步：查看今日重点

优化师从 Luna 工作台、媒体计划或通知中心进入。

系统汇总：

- 今日关键异常；
- 待确认的 Luna 建议；
- 需要执行的策略待办；
- 已完成的定时任务；
- 等待效果验证的动作；
- 需要生成或发送的报告。

#### 第二步：理解问题

优化师进入数据洞察、广告管理或多维分析查看原因。

系统组合：

- 当前指标；
- 历史趋势；
- 目标红线；
- 产品和市场信息；
- 行业知识；
- 品牌历史经验；
- Luna 的判断依据。

#### 第三步：形成决策

Luna 根据适用 Skill 生成建议，优化师可以：

- 采纳；
- 拒绝并说明原因；
- 修改建议；
- 转入本周策略；
- 创建定时任务；
- 添加预警规则；
- 保存数据视图；
- 暂时进入观察。

#### 第四步：执行

不同决策进入对应工作区：

| 决策类型 | 执行位置 |
| --- | --- |
| 预算调整、关停或保留 | 广告管理 |
| 素材替换或新方向 | 素材库、素材生成、草稿中心 |
| 新广告结构 | 草稿中心与批量发布 |
| 周期性工作 | 自动化配置中的定时任务 |
| 指标监控 | 自动化配置中的预警规则 |
| 团队协作事项 | 本周策略待办 |

#### 第五步：验证

执行动作自动进入“动作与复盘”。

优化师查看：

- 执行前指标；
- 执行动作；
- 观察窗口；
- 执行后指标；
- 是否有效；
- 是否需要继续、回滚或调整。

#### 第六步：输出与沉淀

- 结果进入日报、周报或专项报告；
- 有价值的结论形成候选知识；
- 品牌管理员决定是否纳入品牌知识；
- 经过多个品牌验证的共性经验，由平台管理员考虑升级为行业能力。

### 9.3 周度策略动线

```text
复查上周动作效果
      ↓
选择本周核心数据视图
      ↓
结合产品、市场、竞品、目标和品牌知识
      ↓
Luna 调用策略 Skill
      ↓
形成预算、受众、素材和测试建议
      ↓
优化师确认并拆解执行待办
      ↓
本周持续追踪
      ↓
周末生成复盘报告
```

### 9.4 新优化师接手品牌的动线

传统交接依赖前任人员口头说明。本产品中，新优化师可以通过品牌工作空间快速获得：

- 静态品牌画像；
- 产品及核心卖点；
- 经营目标与预算红线；
- 已启用的行业和品牌 Skill；
- 品牌 L4 知识；
- 最近策略；
- 历史动作与效果；
- 报告和客户偏好。

产品因此把个人经验转化为团队可继承的服务资产。

## 10. 各产品模块在体系中的实际作用

### 10.1 Luna

Luna 是能力调度和工作协作入口，不是另一个孤立模块。

它负责理解意图、选择 Skill、组合上下文、解释判断、发起动作和追踪结果。

### 10.2 媒体计划与策略

负责把经营目标转化为周期性行动。

- 月度计划描述整体预算、市场和周次节奏；
- 本周策略负责验证上周期、分析本周期和形成执行待办；
- 它是目标与具体广告动作之间的连接层。

### 10.3 广告管理

负责承接最接近真实投放的执行动作。

- 查看 Campaign、AdSet、Ad；
- 处理预算和素材建议；
- 记录人工调整；
- 将采纳、拒绝和修改反馈给学习系统。

### 10.4 广告创编与批量发布

负责把策略和素材方向转化为待发布广告结构，并完成发布前确认。

### 10.5 创意库

负责管理素材资产、识别疲劳、生成新素材并连接产品卖点与受众方向。

### 10.6 数据洞察看板

负责快速识别经营问题来自账户、渠道、受众、素材还是落地页，是优化师的诊断入口。

### 10.7 多维分析

负责将取数方式保存为可复用的数据视图。

视图不是一次性报表，而是可以被策略、任务、Luna 和报告共同引用的数据语言。

### 10.8 市场与竞品

负责提供广告账户之外的外部环境，使策略不会只根据内部投放数据生成。

有价值的市场与竞品结论可以进入报告、策略或知识库。

### 10.9 报告

负责把数据、洞察、策略、动作和效果组织成可交付的经营结果。

报告也是客户反馈入口，其评分和修改意见可以形成品牌报告偏好。

### 10.10 动作与复盘

负责记录系统和人实际做了什么，并判断是否有效。

它是产品从“会分析”走向“会学习”的关键模块。

### 10.11 品牌信息

负责维护稳定品牌画像，只回答“品牌是谁”。

它不承载产品、竞品或动态投放数据，避免静态画像与动态经营信息混杂。

### 10.12 产品库

负责回答“品牌卖什么”，向素材、策略、Luna 和报告提供产品卖点、受众和市场上下文。

### 10.13 广告账号

负责确定广告数据和执行动作的账号范围。

### 10.14 目标与阶段

负责定义当前经营目标、KPI、预算边界和策略阶段，是所有建议的判断约束。

### 10.15 数据集

负责管理原始数据来源；多维分析负责使用数据。两者职责分离，避免配置与分析混杂。

### 10.16 自动化配置

负责管理品牌的定时任务和预警规则。

- 定时任务用于周期性执行 Skill；
- 预警规则用于持续监控指标；
- 触发后的消息进入通知中心；
- 处理结果进入动作与复盘。

### 10.17 Skill 与知识库

负责管理当前品牌“会什么”和“知道什么”，是品牌服务能力的配置中心。

### 10.18 成员管理

负责明确谁可以使用功能、谁可以改变品牌服务能力。

- 所有者和管理员可以维护 Skill、知识和成员；
- 普通成员使用能力和处理业务，但不能修改能力体系；
- 平台管理员通过独立后台维护行业 Skill 与公共知识。

## 11. 产品中的三条核心闭环

### 11.1 服务执行闭环

```text
发现问题 → 调用 Skill → 形成建议 → 人工确认 → 执行动作 → 验证效果
```

这条闭环保证产品不只提供分析结果。

### 11.2 品牌学习闭环

```text
品牌行为反馈 → 候选知识 → 品牌管理员审核 → L4 知识 / 品牌 Skill
```

这条闭环保证产品越来越理解当前品牌。

### 11.3 平台能力增长闭环

```text
多品牌效果结果 → 共性抽象 → 平台审核 → 行业知识 / 行业 Skill → 再分发
```

这条闭环保证平台的服务能力能够跨品牌增长。

三条闭环叠加后，产品形成双重飞轮：

```text
单品牌越用越贴合
        +
平台服务品牌越多，行业能力越成熟
```

## 12. 权限与责任边界

### 品牌所有者

- 拥有品牌工作空间最终控制权；
- 管理品牌 Skill、知识和成员；
- 确认品牌级规则与服务边界。

### 品牌管理员

- 共同维护品牌能力；
- 管理普通成员、自动化、报告和品牌知识；
- 审核候选经验。

### 普通成员 / 优化师

- 使用计划、广告、素材、洞察和报告；
- 采纳、拒绝或修改建议；
- 执行动作并参与效果验证；
- 不可修改品牌 Skill 和成员体系。

### 平台管理员

- 维护行业 Skill 和公共知识；
- 审核跨品牌抽象出的行业经验；
- 发布能力版本；
- 不直接读取或分发品牌私有知识。

## 13. 产品原则

### 13.1 能力可迁移，品牌数据不可迁移

平台复制方法和知识结构，不复制品牌秘密。

### 13.2 AI 建议必须可解释

每项重要建议需要说明使用了什么 Skill、引用了哪些数据和知识、为什么产生该结论。

### 13.3 高影响动作由人确认

预算、关停和发布等动作必须遵循品牌权限与确认规则。

### 13.4 学习结果先审核再生效

对话、拒绝原因和单次效果不会直接改变正式 Skill 或知识。

### 13.5 动态事实与稳定认知分开

品牌画像、产品、市场动态、实时数据和历史经验分别管理，避免所有内容堆入一个品牌资料页。

### 13.6 产品围绕工作动线，而不是功能数量

功能价值取决于是否能够连接上游依据和下游结果，而不是是否拥有更多页面。

## 14. 产品最终形态

融合后的 AdsGo Marketing OS 应具备三种同时存在的身份。

### 对优化师：日常营销工作台

优化师在一个品牌空间内完成计划、分析、广告、素材、报告和复盘，不需要在多个工具之间重复搬运上下文。

### 对品牌：持续学习的服务档案

品牌的目标、偏好、历史动作和有效经验不会随人员变化而丢失。服务时间越长，系统越理解品牌。

### 对平台：营销能力分发系统

平台可以将专家方法变成行业 Skill，将行业认知组织成公共知识，并将经过验证的新能力持续分发给更多品牌。

产品最终建立的是一套新的服务关系：

```text
平台沉淀行业能力
        ↓
品牌装配适用能力
        ↓
Luna 在品牌上下文中执行能力
        ↓
优化师确认并完成实际服务
        ↓
结果形成品牌经验和行业反馈
        ↓
平台与品牌能力共同进化
```

其核心价值不是“AI 帮优化师多做几个动作”，而是：

> 将优秀营销服务从依赖个人经验的手工作业，升级为可管理、可分发、可迁移、可验证并持续进化的产品能力。
